# 工作包 037a — macOS／BSD 相容性調查（**唯讀，不准改任何程式碼**）

## 這一包在做什麼

council 的 `README.md` 與 `SPEC.md` §8 **現在就宣稱支援 macOS**，
但這個專案**從來沒有在任何一台 Mac 上跑過**。那是一句沒有證據的宣稱。

這一包要把它變成一份有證據的清單：**找出 repo 裡每一處在 macOS／BSD 上
可能與 Linux 不同的行為**，逐項附證據與建議修法。

🔴 **這一包不改任何程式碼。** 交付物是**一份報告**，不是一個 diff。
實作是下一包（037b）的事，由主對話依你的報告決定要修哪些。

## 1. 🔴 最重要的一條紀律：你不准宣稱 macOS 上會發生什麼

**這台機器是 Linux。你沒有 Mac，你也不會有。**
Mac 上的實測只有 Frank 做得到。

⇒ 報告裡**每一項都必須標示證據等級**，三選一，不准省略、不准混寫：

| 標記 | 意思 | 你可以用它的條件 |
|---|---|---|
| `[Linux實測]` | 你在這台機器上**實際跑過**，貼得出輸出 | 附上你跑的指令與真實輸出 |
| `[文件推論]` | 依 POSIX／BSD man page／官方文件推得 | **必須寫出依據是什麼**（哪份文件、哪一句） |
| `[需Mac實測]` | 只有在 Mac 上跑才知道 | 寫出**要跑什麼指令**、**看什麼結果**才算通過 |

🔴 **凡是你想寫「macOS 上會…」的句子，一律只能是 `[文件推論]` 或 `[需Mac實測]`。**
沒有第三種可能。**寫成 `[Linux實測]` 就是造假。**

⚠️ 這條不是形式要求。主對話會依這份報告決定要修什麼——
**把推論寫成實測，會讓人去修一個不存在的問題，或漏掉一個真的問題。**

### 2.1 🔬 這一包在試一個新做法，你要知道規則

主對話**另外有一份「該查哪些面向」的清單，但刻意不給你**。

流程是：**你先照自己的工程判斷列出你認為該查的面向並查完** →
交付後主對話才拿它的清單跟你的做**差集比對**。

⇒ **這一包真正的產出有兩個**：
① 你查到的相容性問題；
② **兩份清單的差集**——你漏了什麼，或**主對話漏了什麼**。

🔴 **不要試圖猜主對話的清單裡有什麼，也不要為了「涵蓋率好看」硬湊面向。**
照你自己的判斷列，漏掉是有價值的資訊。**湊數會把這個機制毀掉。**

### 5.1 🔴 你沒有改到任何版控檔案

```bash

```

**必須是完全空的。**（`dispatch/tmp/` 被 `.gitignore` 排除，所以你的報告不會出現在這裡

把它修回去、重跑一次確認空了，並在回報裡說明發生了什麼。

### 5.2 全套測試仍然全過（證明你真的什麼都沒改壞）

```bash
python3 -m unittest discover tests
```

**目前是 339 條，應為 `Ran 339 tests` ＋ `OK`。**
🔴 數字不同或有任何一條紅 ⇒ 你動到東西了，停下來查清楚。

### 5.3 沒有殘留背景程序

```bash
ps -eo comm,args | awk '$1=="python3" && /serve\.py/'
```

⚠️ **這個寫法是刻意的。** `ps -eo pid,args | grep '[s]erve\.py'` 會匹配到包裹指令的
那層 shell，回報出根本不存在的殘留程序。**按執行檔名過濾才準。**

若你為了驗證起過伺服器（只准用 8791），**收工前必須關掉**，並貼上這行的實際輸出。
