## 缺陷一（嚴重）：長度檢查仍套用在 `prompt` 上，讓 stdin 改造失效

四個 adapter 目前都有這段：

```python
if len(prompt.encode("utf-8")) > MAX_ARG_BYTES:
    ... return ok=False "prompt too long"
```

**但 prompt 現在走 stdin，argv 上只剩 `PROMPT_INDICATOR`。** stdin 沒有
`MAX_ARG_STRLEN` 限制。實測結果：

- `base.run()` 送 180,000 bytes 中文到子行程 → **完整送達，內容完全相符**
- 但 `claude/codex/gemini/opencode` 的 `ask()` 送同一份 → **四家全部
  `ok=False, error="prompt too long (180000 bytes, max 100000)"`**

也就是說這道檢查擋掉了 stdin 完全承受得住的長逐字稿，**本次改造等於白做**。

⚠️ **這主要是我的工作包沒寫清楚**（011 第 2 項只說「改成以位元組比對」，
沒說「不要再套用在 prompt 上」），不是你判斷失誤。`SPEC.md` §4 現已明文禁止。

## 缺陷二（輕微）：`test_run_stdin_text_reaches_child` 的斷言寫在 `with` 區塊外

```python
with tempdir() as tmp:
    capture = tmp / "captured.txt"
    ...
    result = base.run(["fakecli"], 5, stdin_text="payload\nsecond")
self.assertTrue(result["ok"])                    # ← 已跳出 with
self.assertEqual(capture.read_text(), ...)       # ← 暫存目錄已被刪除
```

暫存目錄在斷言執行前就被清掉 ⇒ `FileNotFoundError`。**縮排錯一層**，把兩行斷言
移進 `with` 區塊內即可。

## 規格變更：`model` 改回選填

`SPEC.md` §2.2／§4 已改（**不是你做錯，是前提變了**）：

```python
def ask(prompt: str, model: str | None, timeout_s: int, max_chars: int) -> dict:
```

- `model is None` ⇒ **不得帶上 `--model` / `-m` 旗標**，由該 CLI 自己的設定檔決定
- `model` 為字串 ⇒ 維持現行行為

理由：目標使用者本來就會在各家 CLI 的 config 設好偏好模型，留空是常態路徑；
安全性改由 `model_used`（顯示實際回答者）提供，而非強制事先指定。
⚠️ 但**參數本身不可移除**——同一個 CLI 要開多個席次跑不同模型時只能靠它區分。
